# incident-postmortem

장애 하나를 **사람은 요약과 런북만 읽고도 대응**하고, **에이전트는 증상 대조로 문서를 찾아 명령을 재실행**할 수 있는 형태로 남긴다.

## 산출물

| 파일 | 역할 |
|---|---|
| `docs/incidents/YYYY-MM-DD-<slug>.md` | 포스트모템 본문. 형식은 `assets/template.md` |
| `docs/incidents/README.md` | 날짜·문서·증상·상태 인덱스. 새 문서를 맨 위 행에 추가 |
| `AGENTS.md` | "인시던트 라우팅" 절. 장애 조사 전에 인덱스를 먼저 대조하라는 한 단락 |
| `CLAUDE.md` | `@AGENTS.md` import 한 줄 (Claude와 Codex가 같은 라우팅을 읽게 함) |

날짜는 장애 **발생일**이고, slug는 영문 소문자 증상 요약(`emulator-hang`)이다.

## 절차

1. **사실 수집.** 이번 대화의 조사 결과, 커밋, 로그 실측값만 쓴다. 다시 확인할 수 있는 것은 직접 재확인하고, 확인하지 못한 원인은 "미확인"으로 적는다. 추정을 사실 톤으로 쓰지 않는다.
2. **본문 작성.** `assets/template.md`를 복사해 채운다.
   - frontmatter의 `symptoms`에는 사용자가 실제로 본 오류 문구를 그대로 넣는다. 에이전트가 다음 장애를 대조할 때 쓰는 키다.
   - "증거" 표의 확인 열은 **재실행 가능한 명령**으로 쓴다. 관측값과 해석을 분리한다.
   - "런북"은 판별, 정리, 원인 수집 순서로 쓴다. 파괴적인 명령 앞에는 대상을 확인하는 단계를 둔다.
   - 비난 없는 형식으로, 사람이 아니라 구조와 조건을 원인으로 쓴다.
3. **비밀값과 개인정보 제거.** 호스트명, IP, VPN·Tailscale 주소, 사용자 프로필 경로, 계정명, 토큰은 `%LOCALAPPDATA%`, `<repo>`, `<host>` 같은 자리표시로 바꾼다. 작성 후 grep으로 조사 중 본 실제 값이 남지 않았는지 검사한다.
4. **인덱스 갱신.** `docs/incidents/README.md`가 없으면 아래 헤더로 만들고, 표 맨 위에 행을 추가한다.
   ```markdown
   # 인시던트 기록

   장애 조사 결과를 포스트모템으로 남긴다. 증상이 비슷하면 아래 표에서 먼저 찾고, 문서의 "증거"와 "런북" 절로 같은 사고인지 대조한다.

   | 날짜 | 문서 | 증상 | 상태 |
   |---|---|---|---|
   ```
5. **프로젝트 메모리 라우팅.** 이미 있으면 건너뛴다.
   - `AGENTS.md`에 아래 절을 추가한다(파일이 없으면 `# <프로젝트> 에이전트 메모` 헤더로 만든다).
     ```markdown
     ## 인시던트 라우팅

     장애, 연결 불안정, 프로세스 잔존, 재시작 실패를 조사하거나 고치기 전에 `docs/incidents/README.md`의 증상 열을 먼저 대조한다. 일치하는 문서가 있으면 그 문서의 "증거"와 "런북" 절부터 따른다.
     ```
   - `CLAUDE.md`가 없으면 `@AGENTS.md` 한 줄로 만들고, 있으면 `@AGENTS.md`가 없을 때만 맨 위에 추가한다.
   - 포스트모템 본문을 메모리 파일에 복사하지 않는다. 라우팅만 둔다.
6. **커밋.** 현재 작업 브랜치에 `docs(incident): <요약>` 하나로 커밋한다. push와 배포는 사용자가 요청할 때만 한다.

## 상태 갱신

미해결 항목이 나중에 해결되면 해당 문서의 `status`, "미해결" 절, 인덱스의 상태 열을 함께 고친다. 새 사고가 같은 원인의 재발이면 새 문서를 만들지 말고 기존 문서의 타임라인과 증거에 추가한다.
