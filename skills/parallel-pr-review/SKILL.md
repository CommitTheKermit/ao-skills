# 병렬 PR 리뷰

<!-- usage-stats: skill parallel-pr-review -->

## 절차

1. `github-pr-review` 스킬을 먼저 읽고 그 스냅샷, 검증, 코멘트 규칙을 그대로 적용한다.
2. PR의 base SHA, head SHA, draft와 merge 상태, 변경 파일, 기존 review thread, CI, 선행 PR 의존성을 먼저 고정한다.
3. 정확히 3개의 서브에이전트를 한 메시지에서 동시에 실행한다.
   - `Agent` 도구를 `subagent_type: "general-purpose"`, `model: "opus"`, `effort: "high"`로 호출한다. 이 스킬의 호출 자체가 서브에이전트 사용과 effort 지정에 대한 사용자 요청이다.
   - `fork`를 쓰지 않는다. 새 Agent는 이 대화를 보지 못하므로 필요한 맥락은 프롬프트에 모두 담는다.
   - 세 에이전트에 같은 PR 번호와 고정 SHA, 변경 파일, 기존 thread 상태를 전달한다.
   - diff에 맞춰 서로 다른 위험 관점을 배정한다. 예: 호출 경로와 상태 전이, 오류와 동시성, UI와 플랫폼 경계.
   - 저장소 수정, GitHub 코멘트, approve, request changes는 금지하고 후보만 반환하게 한다.
4. 주 에이전트도 전체 diff와 실제 호출자, 상태 전이, 관련 테스트를 독립적으로 읽는다. 서브에이전트 결과를 대체 자료로 사용하지 않는다.
5. 세 결과를 모두 기다린 뒤 각 후보를 직접 재검증한다.
   - 현재 head의 변경된 오른쪽 줄에서 발생하는지 확인한다.
   - 재현 조건, 사용자 영향, 최소 수정 방향, 반증 조건을 확인한다.
   - 기존 코드 문제, 중복, 추측, 테스트 부재만 지적한 항목, 변경 줄 밖 항목은 제외한다.
6. 보고 직전에 PR head SHA, 상태, review thread, CI를 다시 확인한다. head가 바뀌었으면 새 SHA로 처음부터 다시 리뷰한다.

## 출력과 게시

- 기본 동작은 채팅 보고만 수행한다. 사용자가 명시적으로 게시를 요청하지 않으면 GitHub에 코멘트를 남기지 않는다.
- 발견 사항은 심각도순으로 파일과 변경 줄, 재현 조건, 영향, 최소 수정 방향을 포함해 한 번씩만 보고한다.
- 발견이 없으면 없다고 명시하고, 검토한 SHA와 실행한 테스트, 미검증 범위를 함께 적는다.
- GitHub 게시를 요청받으면 `github-pr-review` 스킬의 변경 줄 인라인 코멘트와 중복 방지 규칙을 따른다.
- 지정한 모델을 쓸 수 없거나 독립 에이전트 3개를 실행할 수 없으면 다른 모델이나 fork로 조용히 대체하지 말고 제한을 보고한다.
