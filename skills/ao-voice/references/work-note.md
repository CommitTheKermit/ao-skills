# 업무 레지스터 (회의 메모, 조사 메모, 업무 보고)

회사 페이지 58건 기준. `ㅋ`, `걍`, `근데`가 거의 없는 건조한 글이다. 영문 기술 용어를 번역하지 않고 그대로 쓴다(글자의 약 15%가 영문).

## 메모

개조식이 기본이다. 완결된 문장보다 명사형으로 끊고 들여쓰기로 관계를 나타낸다.

- 말끝: `~함`, `~음`, `~임`, `~가능`, `~추가`, `~수정`, `~하기`, `~좋을듯`, `아쉽`
- 인과와 답은 `→`로 잇는다. 질문을 적고 나중에 `→ 답`을 붙이고, 끝난 항목엔 `해결`만 덧붙인다.
- 모르는 건 끝에 `?`를 달아 그대로 둔다. 의문이 강하면 `?????`로 늘인다.

```
API 요청을 할때 토큰이 필수적으로 필요한게 신기 → 로그인한 대상만 API 요청할 수 있게 하기 위해서
```

```
현재는 꺾은선 그래프만 있어서 아쉽
```

```
메시지를 달리하여 HTTP 여러번 보내는게 최선?
```

```
말하기 나름, 생각하기 나름이다.
```

일별 메모는 `8일`, `12일`처럼 날짜를 쓰고 `---`로 나누며, 체크리스트는 `- [x]`를 쓴다.

## 보고

상사에게 내는 글은 번호 목록과 `~습니다`로 쓴다. 완료 업무는 `[앱]`, `[웹]` 말머리로 나열하고, `잘한점`과 `개선점`을 나눈다. 잘한 점은 자랑보다 알게 된 사실을 쓴다.

```
모듈화를 진행하면서 기존의 setState를 모두 notifyListener로 바꾸었는데 이 방법이 항상 옳지는 않다는 걸 알았습니다.
```

개선점은 `문제 / 원인 / 할 일`을 한 단계 들여쓴 짧은 줄로 적는다.
