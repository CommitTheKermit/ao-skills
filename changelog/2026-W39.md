## 변경내역 (2026-W39)

### 2026-09-27 - 학습 구현의 결정 이유 주석 점검을 상시화
- 기존: 주석이나 문서화를 별도로 요청받은 경우에만 결정 이유와 제약을 코드 옆에 남기도록 했음
- 변경: 매 구현 단계에서 수정한 모든 파일을 점검하고 비자명한 이유와 제약이 있으면 요청 여부와 무관하게 주석으로 남기도록 명시
- 이유: 학습 과정에서 합의한 설계 판단이 DI 코어 외의 화면과 모델 코드에서도 사라지지 않도록 하기 위해
- 영향 파일: `codex/skills/learn-by-implementing/SKILL.md`, `README.md`

### 2026-09-27 - 학습 구현 설명의 코드 발췌 규칙 보강
- 기존: `learn-by-implementing`은 처음 막힌 지점의 경로와 코드를 보여주도록 했지만, 결과 보고와 다음 단계 안내에서 링크만 남기는 경우를 막지 못했음
- 변경: 파일 링크를 보조 수단으로 규정하고, 질문·진행·결과·다음 단계마다 실제 관련 코드를 경로와 함께 발췌하도록 명시
- 이유: 학습자가 답변마다 코드 위치와 문제 상황을 다시 탐색하는 병목을 없애기 위해
- 영향 파일: `codex/skills/learn-by-implementing/SKILL.md`, `README.md`

### 2026-09-27 - 학습하며 구현하는 Codex 스킬 추가
- 기존: `step-by-step`은 단계별 구현·검증을 다루지만, 실제 코드 위치 제시와 학습자 예측 질문, 정답 공개 시점은 정하지 않았음
- 변경: 학습 질문과 구현 위임을 구분하는 `learn-by-implementing` 스킬 추가
- 이유: 학습자의 사고 과정을 보존하면서 코드 탐색 병목을 줄이고, 승인된 범위만 구현하기 위해
- 영향 파일: `codex/skills/learn-by-implementing/SKILL.md`, `README.md`

### 2026-09-27 - 세션 조사 집계와 구현 범위 보완
- 기존: replay가 같은 root의 최신 파일만 읽고 주입 스킬·브라우저 문맥을 사용자 발언으로 집계할 수 있었음. 구현 절차의 역할·입력 단위·결과 위치와 학습자 작성 범위가 구체적이지 않았음
- 변경: 분할 파일 병합, 파일 간 중복 제외, 사용자 본문 정규화, 고정 ID 목록 집계와 수집 범위 지표를 추가. `intent-first`에 기능 의미, 학습 위임 수준, 실제 반영 위치 확인을 추가
- 이유: 부정확한 빈도에 따른 규칙 승격과 사용자 의도에서 벗어나는 재작업을 줄이기 위해
- 검증: 합성 로그 회귀 검사, 실제 고정 세션 목록 익명 집계, Codex 자산 검증
- 영향 파일: `codex/skills/knowledge-loop/SKILL.md`, `codex/skills/knowledge-loop/replay-audit.py`, `codex/skills/intent-first/SKILL.md`, `README.md`, `changelog/2026-W38.md`
- 출력 변경: `commits`를 `commit_command_candidates`로, 비밀값 지표를 `sessions_with_secret_candidates`로 명확화. 실제 커밋 성공 수나 완전 익명화 보장으로 해석하지 않음
- 동기화 보완: `sync.sh --skills 이름...`과 `verify.sh --skills 이름...`으로 변경한 스킬만 반영·검증. 전체 동기화에서도 폐기된 프로젝트 디자인 훅을 다시 등록하지 않도록 수정
- 추가 영향 파일: `codex/sync.sh`, `codex/verify.sh`, `codex/skills/ao-skill-update/SKILL.md`
