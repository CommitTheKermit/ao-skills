- 기존: 충분한 설명 항목은 있었지만 새 개념을 한 줄로 소개한 뒤 질문으로 넘어가는 일을 막는 점검이 없었답니다.
- 변경: 개념 자체의 의미, 필요성, 구체적 동작과 경계를 먼저 설명하고 질문마다 설명 근거를 확인하도록 했답니다.
- 이유: 이전 코드 이해를 새 개념의 이해로 간주하거나 질문 수를 줄이려고 핵심 설명을 생략하는 일을 방지하기 위함이랍니다.
- 영향 파일: `codex/skills/learn-by-implementing/SKILL.md`, `README.md`

### 2026-10-01: 학습 구현에 개념 설명과 이해 확인 절차 보강

- 기존: 코드 예측 질문 뒤 설명과 구현을 연결해 설명의 깊이와 이해 통과 기준이 불명확했답니다.
- 변경: 소크라테스식 진단, 분해, 설명, 설명 범위에 비례하는 확인 질문, 교정, 통과 판정과 선택 분기를 연결했답니다.
- 이유: 설명을 들은 것과 스스로 이해한 것을 구별하고, 핵심 오해를 재확인한 뒤 작은 구현으로 진행하기 위함이랍니다.
- 영향 파일: `codex/skills/learn-by-implementing/SKILL.md`, `README.md`

### 2026-10-01 - 병렬 PR 리뷰 기준 스냅샷 추가
- 기존: 병렬 담당을 배정할 수 있었지만 위임 전에 최신 SHA, 미해결 리뷰, stacked PR 기준과 CI 상태를 고정하는 순서가 없었음
- 변경: 위임 전 기준 스냅샷을 필수화하고 리뷰 갱신 시 위임 결과를 새 기준으로 다시 검토하며, stacked PR 비교 기준과 PR 메타데이터 실패 분리를 명시
- 이유: 이미 남은 리뷰를 놓치거나 선행 PR 변경까지 중복 검토하는 일을 막기 위해
- 영향 파일: `codex/skills/github-pr-review/SKILL.md`, `README.md`

### 2026-10-01 - PR 리뷰의 검토 범위와 반증 절차 보강
- 기존: 호출자 추적과 최소 검증을 요구했지만 실제 진입 경로, 상태별 검토 근거와 후보 반증 절차는 구체적이지 않았음
- 변경: SHA 기록, 호출자와 상태별 검토 메모, 위험 관점 병렬 분담, 실제 경로 검증, finding 반증과 범위 기준 종료를 추가. 설치본에만 있던 중립적 공개 문체와 인라인 게시 규칙을 원본에도 보존
- 이유: 오류 상태 누락과 호출되지 않는 코드의 장애 오판을 줄이기 위해
- 영향 파일: `codex/skills/github-pr-review/SKILL.md`, `README.md`, `changelog/2026-W39.md`
