# Learn by Implementing

<!-- usage-stats: skill learn-by-implementing -->

첫 동작으로 `python3 "$HOME/.agents/skills/usage-stats/scripts/usage_stats.py" record skill learn-by-implementing >/dev/null 2>&1 || true`를 이 발동에서 한 번만 실행한다.

학습자가 생각할 여지를 유지하면서 실제 작업도 전진시킨다. 학습 질문과 코드 작성 위임은 별개다. 사용자가 직접 작성하겠다고 한 영역은 건드리지 않고, 명시적으로 맡긴 영역만 구현한다.

## 한 번의 학습-구현 순환

1. 현재 파일과 호출 흐름을 읽고, 막힌 지점의 **실제 파일 경로와 관련 코드 몇 줄**을 먼저 보여준다. 기억이나 예시 코드로 현재 구현을 대신하지 않는다. 위치를 찾는 일을 학습자에게 넘기지 않는다.
2. 문제를 한 가지로 좁혀 "이 입력에서 이 줄이 어떻게 동작할까?"처럼 예측이나 이유를 묻는다. 답을 기다리기 전에는 완성된 수정 코드나 다음 단계의 정답을 공개하지 않는다. 단, 사용자가 바로 설명이나 정답을 요청하면 그 수준에 맞춘다.
3. 답변을 현재 코드와 실행 결과에 대조해 맞는 부분과 놓친 조건을 구분한다. 필요한 개념만 설명하고, 핵심 외부 사양은 원문 근거를 확인한다. 다음 질문은 직전 답에서 드러난 빈틈 하나에 집중한다.
4. 학습자가 구현을 맡기면 수정 파일, 변경 범위, 검증 방법을 짧게 예고하고 승인을 받는다. 승인된 한 단계만 구현해 테스트나 실행으로 확인한다. 학습자가 코드를 직접 쓰는 단계라면 힌트, 테스트 이름, 골격 등 요청한 수준에서 멈춘다.
5. 결과와 이유를 연결해 설명한다. 주석이나 문서화를 요청받으면 코드로 드러나지 않는 결정 이유와 제약만 관련 코드 옆에 남긴다. 대화 전체를 주석으로 복사하거나 당연한 동작을 줄마다 해설하지 않는다.

사용자가 질문으로 현재 단계를 중단하면 그 질문을 먼저 해결하고, 다음 단계 구현은 다시 합의한다. `step-by-step`도 적용되는 작업이라면 그 스킬의 승인·검증·보고 절차를 따르고, 이 스킬은 학습 질문의 순서와 설명 깊이를 조절한다. 사용자가 정한 커밋·브랜치 경계는 유지한다.
