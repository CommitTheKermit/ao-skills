# Resume Write

이력서와 포트폴리오의 문구를 새로 쓰거나 고친다. 무엇을 고칠지 아직 모르면 먼저 `/resume-review`로 진단한다.

대상: `$ARGUMENTS`(고칠 블록, 받은 피드백, 원하는 방향). 없으면 지금 대화에서 고르기로 한 항목.

## 형식 원칙

### 블록 구성

- **경력·프로젝트 블록**: 설명 한 줄(무엇을 하는 서비스인가) → 범위 한 줄(무엇을 맡았나) → 이슈 줄(`이슈: 상황 → 한 일`) 한두 개.
- **소개(About)**: 그 사람을 말하는 주장 문장 하나 + 그것을 증명하는 사건 볼릿 두세 개. 주장은 실제로 일어난 사건의 공통분모로 쓴다.
- **라벨 볼릿**: `라벨: 설명`. 굵은 글씨는 라벨(콜론까지)과 `이슈:`에만 준다. 굵은 글씨만 이어 읽어도 목차가 되게 한다.
- 볼릿 문장은 명사형으로 끝낸다(해결, 정리, 운영). 소개의 주장 문장처럼 문장이 필요한 곳만 "~습니다"를 쓴다.
- 한 항목은 가능하면 한 줄. 넘치면 군더더기(조사, 수식어, 예시 개수)부터 줄이고, 고유명사와 숫자는 남긴다.

### 무엇을 남기고 무엇을 빼나

- 결과와 숫자를 앞으로 옮긴다.
- 고유명사(기종, 기술 이름, API 이름)는 지킨다. 표현을 부드럽게 할 때는 태도 낱말만 바꾸고 사실 낱말은 남긴다.
- 넓이와 깊이를 다른 줄에 둔다. 예: 학습 범위 한 줄(다룬 주제 나열) + 사건 한 줄(한 번 깊게 판 것).
- 같은 사건이 두 곳에 나오면 한쪽은 요약, 한쪽은 상세로 역할을 나눈다.
- 한계를 쓰면 다음 과제를 화살표 뒤에 붙인다.
- 동기, 퇴사 이유, "~가 부족해서" 같은 이유 문장은 쓰지 않는다. 면접에서 말로 설명한다.
- 빈자리를 채우려고 늘리지 않는다. 넣을 항목은 JD에서 비어 있는 칸을 기준으로 고른다.
- 합계보다 구성을 쓴다. 시점마다 합계가 달라지는 숫자는 "무엇과 무엇"으로 적는다.

## 근거 경계

- 근거에 없는 수치, 성과, 인과, 기간을 만들지 않는다.
- "본인 회고"인 근거는 쓰기 전에 사용자에게 다시 확인한다. 사용자가 정정하면 그 정정이 우선한다.
- 강도 낱말을 근거에 맞춘다: 발견(직접 찾았을 때만) / 수정, 해결 / 완화(측정 없이 체감만 했을 때), 원인을 찾음 / 단정하지 않음, 검증 / 관찰, 사전 등록(기록으로 시점을 증명할 수 있을 때만).
- 팀 작업, 다른 사람이 발견한 문제, AI가 한 부분을 개인 성과로 쓰지 않는다.
- 기간은 단위를 밝힌다. 영업일 14일을 "2주"로 바꾸지 않는다. 실제보다 짧게 적는 것도 과장이다.
- 무엇을 셌는지 확인되지 않은 숫자는 쓰기 전에 묻는다.
- 공개 저장소·배포 주소만 링크한다. 내부망 주소, 개인 서버 주소는 넣지 않는다.
- 문서끼리 어긋나면 더 조심스럽게 쓴 쪽을 기준으로 삼고, 사용자에게 확인한다.

## 절차

1. **원문 읽기**: 고칠 블록의 실제 글자와 관련 근거 자료를 읽는다. 제목이나 레이어 이름을 원문으로 쓰지 않는다.
2. **사실 질문 먼저**: 기술 이름, 기종, 숫자의 구성, 기간처럼 문구를 좌우하는 사실이 불확실하면 초안보다 질문을 먼저 한다.
3. **전후 비교표 제시**: 위치 | 지금 | 바꿀 문구 | 근거·이유. 줄 수가 중요하면 실제 폭에서 몇 줄이 되는지 재서 적는다. 표 아래에 **빠지는 것**과 **지킨 경계**를 따로 적는다. 대안이 갈리면 권장안 하나를 정해 밝힌다.
4. **승인 후 반영**: 사용자가 고른 안만 반영한다.
   - 쓰기 전에 원문이 비교표의 "지금"과 같은지 확인한다. 다르면 멈추고 알린다. 사용자가 직접 고친 부분을 덮어쓰지 않는다.
   - 기존 서식(글꼴, 크기, 행간, 색, 링크)을 유지한다. 굵기는 정한 범위에만 준다.
   - 문단과 그 소제목처럼 같은 사실을 말하는 짝이 있으면 함께 고친다.
5. **반영 후 확인**: 결과를 다시 보고 줄 넘침, 잘림, 굵기 범위, 링크를 확인한다. 실수를 찾으면 바로 고치고 무엇을 고쳤는지 알린다.
6. **정정 기록**: 사용자가 사실을 정정하면 근거 문서에 날짜와 함께 남긴다. 원본 메모에 틀린 표현이 남아 있으면 사용자에게 알린다.
7. **동기화 점검**: 이력서와 포트폴리오가 같은 숫자, 용어, 기술 이름을 쓰는지, 제목이 고친 내용을 따라왔는지 확인한다.
8. **남은 일 정리**: 기다려야 하는 일(사실 확인, 화면 캡처 등)은 무엇을 기다리는지와 그 뒤 첫 행동을 함께 남긴다.

## 결과 보고

바꾼 위치와 문구, 확인 결과(줄 수, 넘침 여부), 사용자 확인이 필요한 사실, 남은 일을 짧게 보고한다.
