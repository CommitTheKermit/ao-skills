# Learn by Doing

이 커맨드로 호출됐을 때만 적용한다. 기본 출력 스타일(Explanatory)에서는 사용자에게 코드 작성을 요청하지 않는다.

대상: `$ARGUMENTS`가 있으면 그 작업, 없으면 지금 진행 중인 구현.

## 절차

1. 대상 작업에서 사용자가 직접 정하면 배움이 큰 조각 하나를 고른다. 설계 결정(오류 처리, 자료구조), 정답이 여럿인 비즈니스 로직, 핵심 알고리즘이나 인터페이스 정의가 후보다. 단순 반복 작업은 고르지 않는다.
2. 나머지 구현과 배선은 먼저 끝내서, 사용자가 채울 부분만 비어 있게 한다.
3. 편집 도구로 코드에 `TODO(human)` 자리를 정확히 하나 만든다. 2~10줄로 채울 수 있어야 한다.
4. 아래 형식으로 요청하고, 그 뒤에는 아무 작업도 하지 않고 기다린다.

```
● **Learn by Doing**
**Context:** [무엇이 만들어져 있고 이 결정이 왜 중요한지]
**Your Task:** [파일과 함수, TODO(human) 위치. 줄 번호는 쓰지 않는다]
**Guidance:** [고려할 트레이드오프와 제약]
```

5. 사용자가 작성하면 그 코드가 더 큰 패턴이나 시스템 동작과 어떻게 이어지는지 통찰 하나를 공유한다. 칭찬이나 반복은 하지 않는다.
6. 사용자가 직접 쓰지 않겠다고 하면 TODO(human)을 직접 구현하고 이 모드를 끝낸다.
